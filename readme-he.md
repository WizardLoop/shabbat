<a id="docker-installation"></a>
## התקנת Docker

דוגמאות המעטפת מיועדות למסוף Linux/POSIX. פקודות Docker מריצים **במחשב המארח, בשורש הפרויקט שחולץ**, עם הרשאה לשירות Docker. התהליך בתמונה רץ כ־`shabbat`, עם UID/GID ‏`10001`. אין שירות Composer נפרד.

1. קבלו את המקור שנבדק. עבור ארכיון ההכנה לפרסום:

<div dir="ltr">

~~~sh
unzip shabbat-3.0.0-dev.9-publication.zip -d shabbat
cd shabbat
~~~

</div>

הארכיון מכיל מקור ו־`composer.lock`, ללא `vendor/` מותקן. Docker מתקין את תלויות ההרצה הנעולות. **שמרו את `build-info.json` שבארכיון.** בארכיון הפרסום הוא מתעד commit בסיס היסטורי מאומת, `local_changes=true` וטביעת מקור מדויקת של ההכנה; הבסיס אינו commit חדש של השינויים. אם משתמשים בעותק Git שנבדק, מסרו לפני הבנייה את ה־commit האמיתי שלו:

<div dir="ltr">

~~~sh
export BUILD_COMMIT="$(git rev-parse HEAD)"
~~~

</div>

commit הבסיס לבדו אינו מזהה שינויים שטרם נשמרו ב־Git; גם טביעת המקור מזהה את החבילה. אין להחליפו ב־commit לא קשור.

2. צרו פעם אחת תצורה פרטית בהתקנה החדשה:

<div dir="ltr">

~~~sh
cp .env.example .env
chmod 600 .env
~~~

</div>

ערכו את `.env`: החליפו את דוגמאות Telegram, הגדירו `ADMIN`, חשבון GeoNames לפי הצורך ו־`SOURCE_URL` למקור התואם שתעמידו לרשות המשתמשים. שמרו על תחביר פשוט של `KEY=value`, המתאים ל־PHP raw INI ול־Compose. הקובץ המוגדר אינו מיועד להעלאה למאגר.

3. בנו ובדקו את התמונה. השלבים מתקינים ומתקנים תלויות וכותבים נתוני זיהוי בתוך התמונה, בלי להפעיל את הבוט:

<div dir="ltr">

~~~sh
docker compose build
docker compose run --rm --no-deps shabbat php bin/self-check.php --release
docker compose run --rm --no-deps shabbat php bin/runtime-permissions.php --require-non-root
~~~

</div>

4. אתחלו **מסד חדש וריק**, כשהשירות עצור. למסד קיים נדרש נוהל שדרוג וגיבוי.

<div dir="ltr">

~~~sh
docker compose run --rm --no-deps shabbat php bin/migrate.php --writers-stopped --db /app/data/shabbat.sqlite
~~~

</div>

5. הפעילו כשמוכנים לחיבור אמיתי ל־Telegram ולפעילות בקבוצות הרשומות:

<div dir="ltr">

~~~sh
docker compose up -d shabbat
docker compose ps
docker compose logs --tail=100 shabbat
docker compose exec shabbat php bin/health.php
~~~

</div>

שם השירות: `shabbat`. כרכים: `bot-data` ב־`/app/data`, ו־`madeline-session` ב־`/app/runtime`; השמות בפועל כוללים את שם פרויקט Compose. שמרו את זהות הפרויקט והכרכים בשדרוג. Compose כופה `DATA_DIR=/app/data` ו־`SESSION_PATH=/app/runtime/bot.shabbat`. בדיקת הבריאות הראשונית ממתינה לשני המתזמנים; תקופת ההתחלה המוגדרת היא 90 שניות.

<a id="manual-installation"></a>
## התקנה ידנית

השתמשו במקור נפרד ובחשבון שירות שאינו root ושיכול לכתוב לתיקיות העבודה, הנתונים והסשן. הריצו **משורש הפרויקט הזה**, לאחר העתקת והגדרת `.env` כמתואר:

<div dir="ltr">

~~~sh
composer install --no-dev --no-interaction --prefer-dist --optimize-autoloader
composer check-platform-reqs --no-dev
mkdir -p data/session
php bin/self-check.php --release
php bin/runtime-permissions.php --require-non-root
php bin/migrate.php --writers-stopped --db data/shabbat.sqlite
php bot.php
~~~

</div>

הפקודה האחרונה מפעילה את הבוט בחזית ומתחברת ל־Telegram. עצרו באמצעות Ctrl+C והמתינו לסיום; הפעלה חוזרת נעשית ב־`php bot.php`. ניהול תהליך ידני באחריות המפעיל; אין בפרויקט יחידת systemd מוכנה. Windows מתאים לרבות מהבדיקות הלא־מקוונות, אך בדיקת POSIX של משתמש שאינו root ובדיקת פריסת Linux דורשות מארח מתאים.

Composer מחיל ומאמת את התיקונים המקומיים בהתקנה רגילה. אם הסקריפטים בוטלו, הריצו **בהתקנה העצורה**:

<div dir="ltr">

~~~sh
composer install --no-dev --no-scripts --no-interaction --prefer-dist
php scripts/apply-patches.php
php scripts/verify-patches.php
~~~

</div>

תוכן תלות לא מוכר או תיקון חלקי גורמים לכישלון אימות. החלה חוזרת אינה משנה מקור שכבר תוקן כראוי. אין לתקן ספרייה מותקנת בזמן שהבוט משתמש בה.

<a id="configuration"></a>
## תצורה

הבוט קורא את `.env` שבשורש כ־raw INI. ערכי סביבה לא ריקים קודמים לקובץ בחיפוש פרטי התחברות ונתיבים; הימנעו מהגדרות כפולות וריקות. גם כלי התחזוקה קוראים את `.env` לפתרון נתיבים; `--db` מפורש בוחר את מסד היעד. נתיבים יחסיים מתחילים בשורש הפרויקט.

| משתנה | ברירת מחדל / דרישה | תפקיד |
|---|---|---|
| `API_ID` | מספר שלם חיובי, חובה | מזהה יישום Telegram. |
| `API_HASH` | 32 תווים הקסדצימליים, חובה | סוד יישום Telegram. |
| `BOT_TOKEN` | חובה | טוקן BotFather של ההתקנה. |
| `ADMIN` | יש להגדיר לגישת מפעילים | מזהים/שמות ניתנים לפענוח, מופרדים בפסיק; מזהים מספריים מונעים עמימות. הבעלים המוגדרים שומרים גישת התאוששות והפעלה מחדש. |
| `DATA_DIR` | `data` בפרויקט | נתוני היישום ו־BroadcastManager; ב־Compose מוחלף ב־`/app/data`. |
| `APP_DB_PATH` | `DATA_DIR/shabbat.sqlite` | מסד היישום; בדוגמה מוגדר במפורש `data/shabbat.sqlite`. |
| `SESSION_PATH` | `bot.shabbat` בפרויקט | סשן MadelineProto; בדוגמה `data/session/bot.shabbat`, וב־Compose ‏`/app/runtime/bot.shabbat`. |
| `HEARTBEAT_PATH` | `DATA_DIR/scheduler-heartbeat.json` | קובץ פעימות מתזמני ההרשאות וההודעות. |
| `LEGACY_DATA_PATH` | שורש הפרויקט | שורש מקור ישן לקריאה בלבד עם `data/DBgroups.txt`; בעת עלייה נוספים רק רישומי קבוצות חסרים. |
| `GEONAMES_USERNAME` | ריק | חשבון webservices שלכם; demo אינו נתמך. |
| `GEONAMES_ENDPOINT` | `https://secure.geonames.org` | נקודת HTTPS מאומתת, ללא מעבר ל־HTTP. |
| `CUSTOM_EMOJI_ENABLED` | `1` | `0` בוחר אימוג׳ים בסיסיים; גם דחיית זכאות ודאית מפעילה חלופה מבוקרת. |
| `SOURCE_URL` | ריק; יש להגדיר לפני פריסה | URL ב־HTTPS למקור המדויק. חוסר בהגדרה מדווח, אך אינו חוסם עלייה. |
| `BUILD_COMMIT` | נתוני הארכיון או commit בן 40 תווי hex | זהות בנייה/ריצה ופרמטר בניית Compose. שומרים גם טביעות מקור לשינויים מקומיים. |

<a id="telegram-setup"></a>
## הכנת Telegram

1. קבלו פרטי API דרך [ניהול יישומי Telegram](https://my.telegram.org/apps).
2. צרו או בחרו את הבוט ב־[BotFather](https://t.me/BotFather), קבלו טוקן ואפשרו הוספה לקבוצות.
3. פתחו את הבוט בפרטי באמצעות `/start`. הוסיפו אותו לקבוצה עם הרשאות להגבלת חברים ולשינוי הרשאות ברירת מחדל. מחיקה ונעיצה אופציונליות דורשות את הרשאות Telegram המתאימות.
4. הפעילו `/setinline` ב־BotFather לחיפוש ושיתוף באינליין. טקסט מוצע: `shabbat · zmanim · daf · omer · loc city`. חיפוש בשם עיר אינו דורש `/setinlinegeo` או `/setinlinefeedback`; שיתוף GPS מפורש.
5. עם הרשאת שינוי תפריטים, שלחו בפרטי `/setcommands all all preview` לצפייה בכמות התפריטים; `/setcommands all all` מעדכן אותם ב־Telegram. מנהל קבוצה אינו מקבל מכך הרשאה זו.

ניקוי אופציונלי מטפל רק בעדכונים ש־Telegram מוסר לבוט. לקבלת הודעות כלליות מבוטים אחרים, הבוט המקבל צריך **Bot-to-Bot Communication Mode** פעיל דרך BotFather, הרשאת מנהל בקבוצה ו־**Group Privacy Mode** כבוי, כמפורט ב[תיעוד Telegram לתקשורת בין בוטים](https://core.telegram.org/api/bots/bot-to-bot). המחיקה עדיין דורשת הרשאה מתאימה; אין בכך הבטחה לקבלת כל הודעה.

<a id="group-setup"></a>
## הוספת קבוצה

1. שלחו `/add` **בקבוצה, כמנהלי הקבוצה**. קבוצה חדשה שמתווספת כך מתחילה **כבויה**, וההגדרות נפתחות בפרטי.
2. אשרו את שם הקבוצה, המיקום, אזור IANA ולוח ישראל/חו״ל. יש לבדוק את ערכי ברירת המחדל של ירושלים; הם אינם מיקום שנקבע אוטומטית.
3. בחרו מצב ומדיניות שבת/חג, ואחר כך שיטות נרות/הבדלה והיסטים תפעוליים.
4. הפעילו במפורש את מודולי היום/דף/תפילין/עומר הרצויים. צפו בתצוגה מקדימה בפרטי; בדיקה בקבוצה דורשת אישור נפרד ומוגבלת בקצב.
5. חזרו דרך `/groups` בפרטי או `/settings` בקבוצה. הגדרות אישיות וקבוצתיות נפרדות.

**הסתייגות במימוש הרישום הנוכחי:** גם `/settings` יכול לרשום קבוצה לא מוכרת אחרי אימות המנהל, ונתיב זה יורש מהמסד מצב **נעילה**. השתמשו ב־`/add` למסלול המתחיל במצב כבוי ובדקו מיד מיקום ומצב. `/settings` אינו מפעיל מחדש קבוצה שהוסרה; `/add` יכול. זו ההתנהגות הקיימת, והיא לא שונתה בסתר במסגרת הכנת הפרסום.

הפאנלים מציגים ערכים קיימים, עבודה קרובה ומצב התאוששות. שינוי דורש הרשאה עדכנית ואישור הקשור למשתמש, לקבוצה ולגרסת ההגדרות. נושא פורום חסר או סגור יוצר שגיאה, ולא הפניה לנושא אחר. השחזור משתמש בהרשאות המקוריות; צילום חסר, לא מאומת או מתנגש דורש פתרון מורשה. ניקוי הודעות חברים ובוטים מתחיל כבוי. חוב שחזור לא פתור חוסם הסרת קבוצה.

## מיקום ושפות

קיימים שישה קטלוגי שפה: עברית `he`, אנגלית `en`, רוסית `ru`, צרפתית `fr`, ספרדית `es` ופורטוגזית ברזילאית `pt-br`. נבדקים מפתחות ומצייני ערכים; אין בכך הבטחה לתרגום כל שגיאת צד שלישי או ממשק ישן. נוסח התפילה העברי נשאר עברי, לצד טקסט הסבר כאשר הוא מסופק. תפריטי Telegram משתמשים ב־`pt`; שפת התפריט לפי הלקוח ושפת הבוט השמורה הן הגדרות נפרדות.

השתמשו ב־`/preferences` או `/language` בפרטי; `/language` בקבוצה מחייב ניהול קבוצה. לחיפוש עיר, פתחו [חשבון GeoNames](https://www.geonames.org/login), הפעילו free webservices והגדירו `GEONAMES_USERNAME`.

בפאנל המתאים: **מיקום ואזור זמן → חיפוש עיר באינליין → עיר/מדינה/אזור → בדיקת קואורדינטות ואזור זמן → אישור היעד ששמו מוצג**. קיימים גם חיפוש פרטי, ערים מוכרות, קואורדינטות, חיפוש אזור IANA ותשובת GPS לפי בקשה. הבחירה זמנית, שייכת למשתמש אחד וחד־פעמית. שינוי אזור זמן אינו מזיז קואורדינטות.

חיפוש אינליין ציבורי `loc city` או שם עיר בלבד מאפשר חיפוש ושיתוף מיקום. חיפוש אזור זמן ציבורי אפשרי באמצעות `tz Jerusalem` או `Asia/Jerusalem`, ללא שינוי הגדרות. שאילתות ההגדרה `location CITY` ו־`timezone QUERY` דורשות בקשת מיקום או אזור זמן פעילה בפרטי ומובילות לאישור. המצבים הנוספים: `shabat`, `shabbat`, `שבת`, `zmanim`, `daf`, `omer`. בדקו את המיקום המוצג: שיתוף אישי ותצוגה מורשית בהקשר קבוצה עשויים להשתמש בהגדרות שונות. תקלות חשבון ומכסה נשארות שגיאות גלויות.

<a id="operations"></a>
## תפעול

פקודות Docker רצות **במארח, באותו שורש ובאותה זהות פרויקט**, עם גישה לשירות Docker. פקודות PHP רצות **בתמונה ב־/app**, או בשורש התקנה ידנית כמשתמש השירות. פלט תפעולי עלול לכלול מזהי קבוצות ומצב; שמרו אותו בפרטיות.

| פעולה | פקודה | השפעה או תנאי |
|---|---|---|
| בנייה | `docker compose build` | בנייה מהמקור ומה־lock. |
| הפעלה | `docker compose up -d shabbat` | הפעלה/יצירה מחדש וחיבור ל־Telegram. |
| עצירה | `docker compose stop shabbat` | עצירה מסודרת עם 60 שניות חסד; הכרכים נשמרים. |
| הפעלה מחדש | `docker compose restart shabbat` | הפעלת אותו שירות מחדש; ללא בניית תמונה. |
| מצב | `docker compose ps` | מצב השירות והמכולה. |
| לוגים | `docker compose logs --tail=100 shabbat` | צפייה בלוגים; `--follow` למעקב, Ctrl+C מסיים את הצופה. |
| בריאות | `docker compose exec shabbat php bin/health.php` | סכמה וחיבור, שתי פעימות ומדדי תורים/נעילות. |
| בריאות מעמיקה | `docker compose exec shabbat php bin/health.php --deep` | גם שלמות ומפתחות זרים; פעולה יקרה יותר. |
| בדיקת שחרור | `docker compose run --rm --no-deps shabbat php bin/self-check.php --release` | בדיקות פלטפורמה ותיקונים ללא חיבור לבוט. |
| בדיקת כתיבה | `docker compose run --rm --no-deps shabbat php bin/runtime-permissions.php --require-non-root` | בדיקת קבצים זמניים; עשויה להוסיף שורה ללוג תהליך קיים. |

שתי פעימות המתזמן חייבות להיות בנות 180 שניות לכל היותר. מסד משוחזר או מנותק עשוי לעבור בדיקות מבנה ובכל זאת להחזיר `healthy=false` וקוד יציאה 1 ללא מתזמנים. אין ליצור פעימות מלאכותיות.

כלי התחזוקה הישירים מופעלים **משורש הפרויקט כמשתמש השירות**. ב־Docker מקדימים לפקודת PHP ‏`docker compose run --rm --no-deps shabbat` ומשתמשים בנתיבי המכולה. `--writers-stopped` הוא הצהרת המפעיל ולא פקודת עצירה.

| פעולה | פקודה | השפעה או דרישה |
|---|---|---|
| מיגרציה | `php bin/migrate.php --writers-stopped --db data/shabbat.sqlite --backup-dir backups` | כל הכותבים עצורים ותיקיית גיבוי קיימת; גיבוי מסד קיים והחלת מיגרציות. מוותרים על הגיבוי רק למסד חדש. |
| גיבוי | `php bin/backup.php --db data/shabbat.sqlite --directory backups --keep 7` | העתק SQLite עקבי ומניפסט, שמירת שבעה גיבויים בשם הכלי. אפשר בתחזוקה בזמן פעילות. |
| שחזור | `php bin/restore.php --backup backups/CHOSEN.sqlite --db data/shabbat.sqlite --writers-stopped` | גיבוי נבחר ומאומת, כותבים עצורים; היעד הקודם נשמר. |
| בדיקת ייבוא | `php bin/import-legacy.php --db data/shabbat.sqlite --legacy /path/to/legacy-copy --dry-run` | בדיקה ודוח, ללא כתיבת רשומות מיובאות או פעולות Telegram. |
| החלת ייבוא | `php bin/import-legacy.php --db data/shabbat.sqlite --legacy /path/to/legacy-copy --apply --writers-stopped --backup-dir backups` | מסד שעבר מיגרציות, תיקיית גיבוי וכותבים עצורים; ייבוא תוספתי. |
| אבחון לוח | `php bin/check-calendar.php --date=2026-10-15` | HTTPS ציבורי בלבד; ללא DB, ‏.env או סשן. `--help` מציג קואורדינטות/אזור/לוח/שפה. |
| אימות תיקונים | `php scripts/verify-patches.php` | בדיקת התוכן המותקן המאושר. |
| החלת תיקונים | `composer patches` | החלה ואימות; בהתקנה עצורה בלבד. |
| זיהוי בנייה | `php bin/build-metadata.php --commit=YOUR_40_HEX_COMMIT` | מחליפים את מציין המקום במקור מאומת; כתיבת זיהוי ודחיית טביעה לא תואמת. |

<a id="upgrade-and-legacy-import"></a>
## שדרוג וייבוא מהגרסה הישנה

שמרו תצורה פרטית, נתונים וסשן ואת זהות פרויקט Compose. השתמשו במקור ו־lock שנבדקו; עצרו כל כותב לפני שינוי סכמה או תלויות מותקנות. שדרוג רגיל נעשה עם `composer install`, ולא עם `composer update`.

למסד Compose קיים, מתוך הפרויקט המוכן המחובר ל־**אותם כרכים**:

<div dir="ltr">

~~~sh
docker compose build
docker compose stop shabbat
docker compose run --rm --no-deps shabbat mkdir -p /app/data/backups
docker compose run --rm --no-deps shabbat php bin/backup.php --db /app/data/shabbat.sqlite --directory /app/data/backups --keep 7
~~~

</div>

השלימו גיבוי סשן ו־BroadcastManager כשהם עצורים ותרגול שחזור, כמתואר בהמשך, **לפני המשך העבודה**. לאחר מכן הריצו את המיגרציה ובדיקת השחרור:

<div dir="ltr">

~~~sh
docker compose run --rm --no-deps shabbat php bin/migrate.php --writers-stopped --db /app/data/shabbat.sqlite --backup-dir /app/data/backups
docker compose run --rm --no-deps shabbat php bin/self-check.php --release
~~~

</div>

`docker compose up -d shabbat` מפעיל לאחר מכן את התמונה שנבדקה; בדקו לוגים ובריאות. הסדר בהתקנה ידנית: עצירה, גיבוי, התקנה מה־lock, מיגרציה, בדיקה והפעלה.

מעבר מ־dev.8 ל־dev.9 מוסיף `016_delivery_safety.sql`. מ־dev.6 נדרשות גם 013–015; גרסאות מוקדמות מחילות אוטומטית את כל החסרות. אין לערוך SQL שכבר הוחל. ניסיונות מסירה קודמים שלא הוכרעו מטופלים בזהירות; צילומי הרשאות ישנים שאינם מאומתים עדיין דורשים בדיקת מנהל.

במעבר מהבוט הישן מבוסס הקבצים: שמרו עותק מוגן, עצרו את הכותבים הישנים לייבוא הסופי ולמעבר, אתחלו מסד חדש, בצעו dry-run, השוו ספירות/תבניות/הרשאות/אזהרות ואז החילו עם כותבים עצורים ותיקיית גיבוי. הפקודות המדויקות מופיעות לעיל. ב־Docker חברו רק את העותק המוגן לקריאה בלבד:

<div dir="ltr">

~~~sh
docker compose run --rm --no-deps --volume /absolute/path/legacy-copy:/legacy:ro shabbat php bin/import-legacy.php --db /app/data/shabbat.sqlite --legacy /legacy --dry-run
~~~

</div>

ייבוא מפורש משמר לפי הנתונים קבוצות, תבניות/ישויות/מדיה/כפתורים, טיוטות, נמענים מוכרים ועדויות הרשאות, ללא קריאות Telegram. המודולים החדשים נשארים כבויים; צילום חסר או פגום נשאר לטיפול. הגשר של `DBgroups.txt` בעת עלייה מוסיף רישומים בלבד ואינו מחליף ייבוא מלא. אין להחליף נתוני ייצור במסד או בסשן של בוט בדיקה.

## גיבוי וחזרה לגרסה קודמת

גיבוי SQLite משתמש ב־`VACUUM INTO`, מאמת שלמות, מפתחות זרים והיסטוריית סכמה וכותב נתוני SHA-256. העתקת הקובץ הראשי החי בלבד עלולה להשמיט נתונים שכבר נכתבו ל־WAL. שמירת הגיבויים מוחקת רק שמות מדויקים של הכלי בתיקייה שנבחרה; בחרו `--keep` במכוון.

SQLite **אינו** כולל את הסשן ואת כל קובצי BroadcastManager. עצרו את הכותבים ושמרו בנפרד נתיבים אלה, תצורה פרטית וקוד/lock תואמים לצד גיבוי המסד. דוגמת Docker **לאחר עצירת השירות**, משורש הפרויקט במארח. השתמשו בתיקיית עותק חדשה וריקה לכל גיבוי (החליפו את `../shabbat-private-backup` באופן עקבי):

<div dir="ltr">

~~~sh
mkdir -p ../shabbat-private-backup
chmod 700 ../shabbat-private-backup
docker compose cp shabbat:/app/data ../shabbat-private-backup/data
docker compose cp shabbat:/app/runtime ../shabbat-private-backup/runtime
cp .env ../shabbat-private-backup/config.env
chmod 600 ../shabbat-private-backup/config.env
~~~

</div>

כך מועתקות תיקיות הנתונים המתמשכים כשהתהליך עצור לתיקייה מקבילה מחוץ להקשר הבנייה של Docker. שמרו אותן בפרטיות ומחוץ לחומר הפרסום. בהתקנה ידנית העתיקו את נתיבי הנתונים והסשן האמיתיים כשהכותבים עצורים. אמתו גיבויים לפני החלפה.

צרו תיקיית תרגול נפרדת ושחזרו אליה גיבוי SQLite נבחר ומאומת:

<div dir="ltr">

~~~sh
mkdir -p ../shabbat-rehearsal
php bin/restore.php --backup backups/CHOSEN.sqlite --db ../shabbat-rehearsal/restored.sqlite --writers-stopped
php bin/health.php --db ../shabbat-rehearsal/restored.sqlite --deep
~~~

</div>

החליפו `CHOSEN.sqlite` בשם האמיתי. בדקו שדות מבנה, סכמה ודגימת רשומות; בדיקת הבריאות הכוללת עשויה לצאת ב־1 ללא פעימות חיות.

חזרה לגרסה קודמת: עצרו כותבים, שמרו גיבוי התאוששות עדכני, פתרו או תעדו חובות הרשאה ב־Telegram, שחזרו מסד/קוד/lock/סשן/מצב BroadcastManager תואמים, הפעילו עותק יחיד ובדקו התאמה להרשאות מרוחקות טריות. שחזור מסד אינו מבטל שינוי שכבר התקבל ב־Telegram. כלי השחזור מאמת קלט ומניפסט, מקבל נעילת כותב ושומר `*.before-restore-*`. כותב עסוק או סכמה לא תואמת דורשים בדיקה, ולא מחיקת נעילות או כרכים.

[גיבוי ושחזור מפורטים](docs/BACKUP_RESTORE.md)

| תסמין | פעולה |
|---|---|
| commit חסר או מקור ששונה בזמן הבנייה | שמרו נתוני ארכיון מאומתים או מסרו זהות אמיתית של עותק שנבדק. לאחר שינוי מקור מפיקים מחדש נתוני ארכיון. |
| בדיקת שחרור SQLite נכשלת | השתמשו בתמונה הנעולה או בסביבה מתוקנת ומתקבלת; אזהרת פיתוח אינה אישור ייצור. |
| סכמה חסרה או ישנה | עצרו כותבים, גבו והריצו מיגרציה לנתיב מפורש. העלייה אינה מבצעת מיגרציה. |
| כישלון תיקון | בדקו lock ומניפסטים והתקינו בעותק נקי ועצור; אין להחליש אימות. |
| קבוצה חדשה לא שולחת | בדקו מצב, מיקום, הפעלת מודול ותזמון; `/add` מתחיל כבוי. |
| הגדרות חסומות או פגו | פתחו שיחה פרטית ופאנל `/settings` חדש כמנהלי הקבוצה הנוכחיים. |
| חיפוש עיר נכשל | בדקו הפעלת GeoNames, חשבון, מכסה ו־HTTPS; השתמשו בעיר מוכרת או בקואורדינטות לפי הצורך. |
| מצב לא בריא | בדקו גיל שתי הפעימות, סכמה, תור ולוגים; מתזמן עצור אינו מעדכן פעימה. |
| קבוצה לא נפתחת | השתמשו בהתאוששות ובאבחון לצילומים חסרים/לא מאומתים/מתנגשים ושמרו הגבלות מקוריות. |
| תזכורת חסרה או מאוחרת | בדקו אזור זמן/תאריך, שקט, מדיניות חג וסיום, מודול ונושא. הזכאות נבדקת במסירה. |
| דחיית אימוג׳י מותאם | הגדירו `CUSTOM_EMOJI_ENABLED=0`; גם דחיית זכאות ודאית מפעילה חלופה. |
| שגיאת הרשאות קבצים | בדקו UID/GID ‏10001 ונתיבי עבודה/נתונים/סשן, והריצו בדיקת כתיבה. הימנעו מהרשאת כתיבה לכולם. |

## מבנה הפרויקט ופיתוח

| נתיב | תוכן |
|---|---|
| `bot.php`, `src/` | כניסה לבוט ושירותי לוח, ממשק, תזמון, אחסון, Telegram וריצה. |
| `bin/`, `migrations/` | תחזוקה ושינויי סכמה ממוספרים שאינם משתנים אחרי החלה. |
| `resources/` | שש שפות, מקורות עומר מיוחסים ותצורת PHP. |
| `patches/` | מקורות בסיס ותוכן מתוקן שנבדקו, diffs, מקור וחתימות SHA-256. |
| `tests/` | בדיקות ונתוני JSON/TXT/PHP חיוניים. |
| `scripts/` | תיקונים, איכות, תלויות ואריזה מקומית. |
| `docs/`, `LICENSES/` | מדריכים, מקור ורישיונות. |
| `.github/` | תהליכי CI ושחרור ותבניות תרומה ואבטחה. |

הריצו **בשורש עותק פיתוח נפרד, כחשבון המפתח**, ללא נתוני ייצור או סודות. ההתקנה כוללת כלי בדיקה; הבדיקות משתמשות במצב זמני מבודד.

<div dir="ltr">

~~~sh
composer install --no-interaction --prefer-dist
composer validate --strict --no-check-all
composer check-platform-reqs
php scripts/verify-patches.php
composer test
composer lint
composer style
composer analyse
composer check-locales
composer check-docs
composer self-check
~~~

</div>

האפשרות `--no-check-all` מדלגת על עצת טווח גרסאות כללית בשל נעילת MadelineProto המדויקת; בדיקות סכמה ו־lock מחמירות נשארות. `lint` בודק תחביר ואיכות, `style` אוכף שגיאות PHPCS ו־`analyse` מפעיל PHPStan. ‏`composer style-review` מציג דוח סגנון רחב יותר; `composer style-fix` **משכתב קבצים**, ולכן מיועד לעותק פיתוח מבוקר בלבד.

באותו שורש פיתוח:

<div dir="ltr">

~~~sh
composer show --locked --format=json
composer licenses --format=json
composer audit --locked --format=json
composer dependencies
~~~

</div>

הפקודות מדווחות על חבילות נעולות, רישיונות מותקנים והתראות עדכניות; audit פונה לשירותי התראות. `dependencies` כותב עדויות ב־`docs/`; בדקו וסננו אותן לפני הכללה. אין להחליף lock כדי להשתיק בדיקה.

הפקת תיקונים מחדש למפתחים בלבד, משורש עותק הפיתוח:

<div dir="ltr">

~~~sh
php patches/madelineproto/generate-artifacts.php
php patches/broadcastmanager/generate-artifacts.php
~~~

</div>

הפקודות משכתבות תוצרי תיקון ומניפסטים מהמקורות המצורפים שנבדקו. הן מיועדות לסקירת תיקון יזומה, ולא להתקנה רגילה. בדקו חתימות ו־diffs ששונו והריצו לאחר מכן את כל בדיקות התיקונים. סקריפטי ההחלה והאימות ב־PHP מקבלים גם פרמטר מיקום ראשון אופציונלי לתיקיית vendor; השאירו אותו ריק לשימוש רגיל ב־`vendor/`.

לאריזה מקומית עם תלויות הפיתוח הנדרשות וזיהוי מאומת:

<div dir="ltr">

~~~sh
php scripts/package.php
~~~

</div>

הכלי כותב ZIP ליישום, למקור תואם ולשרת בדיקה, עם חתימות ומניפסטים ב־`dist/`, ללא פרסום. המסירה הנפרדת כאן משתמשת ב־`*-publication.zip` ללא תלויות מותקנות ובחבילת מקור תואם עם מלאי נפרד. בדקו בכל מניפסט מה כלול ומה הוחרג; מקור היישום ו־lock אינם לבדם חבילת מקור תלויות מלאה.
