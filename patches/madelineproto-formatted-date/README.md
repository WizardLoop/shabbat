# MadelineProto formatted-date entity compatibility

Prepared 2026-10-14 for exact MadelineProto 8.7.0 commit 7b99dd0f2d964a492c377912ffce9f5ce61aa9ed. This reviewed upstream release is a prerelease; it is not described as the latest stable release. The installed layer 225 schema declares `messageEntityFormattedDate#904ac7c7`, but the unchanged `MessageEntity::fromRawEntity` factory throws `AssertionError` before message dispatch. The public v8 source reviewed on this date still lacked the factory arm, so no tested compatible official version eliminated this local fix.

The immutable [factory source](https://github.com/danog/MadelineProto/blob/7b99dd0f2d964a492c377912ffce9f5ce61aa9ed/src/EventHandler/Message/Entities/MessageEntity.php) was downloaded and byte-matched to the locked installation. Its pristine SHA256 is 06a9d438cc198f56cfb745a2a3808932269033671146cf82f84ae88e8d6eae60. The complete original schema and upstream license are retained beside that baseline. All exact input, output, schema, diff, class and license hashes are in manifest.json.

The single unified diff adds two exact factory arms and a new independently authored `FormattedDate` class. The class preserves inherited readonly UTF-16 offset/length, an integer Unix timestamp and all six native flags. It emits/accepts official BotAPI `date_time` (`unix_time`, `date_time_format`) and retains the native MTProto constructor. Integer fields and boolean flags are validated without lossy numeric coercion. Relative/other flags, simultaneous short/long time and simultaneous short/long date are rejected. Empty format preserves the linked original text. See [native constructor](https://core.telegram.org/constructor/messageEntityFormattedDate) and [official format grammar](https://core.telegram.org/bots/api#date-time-entity-formatting).

The wrapper accepts nonnegative native int32 timestamp/position values. Telegram enforces its own date horizon when a real send is performed; the local wrapper does not use the machine clock to alter an incoming or replayed timestamp. No general unknown-entity fallback is added. Existing entity handlers remain unchanged. The installed generic HTML renderer preserves original text and ordinary surrounding formatting, but does not generate a special date tag; native capture/storage/resend preserves the date entity instead of routing it through HTML.

## Installation and refusal states

The installer checks exact installed version/commit, complete baseline/diff/reviewed output/license/schema hashes and contained regular targets. The factory and new class are one state: pristine factory plus absent class may be applied; exact reviewed factory plus exact reviewed class succeeds without change. Either partial combination, changed/unrecognized class/factory, symlink/directory, incorrect schema/version or tampered source artifact stops the build. No unknown hash is called upstream-supported, and partial states are not silently repaired.

Run php scripts/apply-patches.php and php scripts/verify-patches.php before bot startup. Composer and Docker execute the shared five-patch lifecycle; the explicit --no-scripts installation path runs the same two commands. The application writer lock prevents mutation of a running installation. A staged addition is installed exclusively before atomic factory replacement; an interruption between files is a detectable partial state and requires explicit maintenance review. Never patch an active process or container. Vendor is not tracked in Git and no mutable patch is fetched during build.
