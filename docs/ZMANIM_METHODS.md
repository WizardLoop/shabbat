# Calculation methods

Times depend on location, timezone, calendar scheme and chosen method; this is not personal halachic advice.

Candle lighting uses either city custom or an explicit integer 1–120 minutes before sunset. Presets are exactly 10, 15, 18, 20, 22, 30 and 40. Hebcal defaults are Jerusalem 40, Haifa/Zikhron Yaakov 30, elsewhere 18. An API check of the legacy Jerusalem `b=18` query returned the same 40-minute result as city default; importing groups preserves that actual behavior.

Havdalah method/value are separate. Degrees 8.5 uses the provider's `tzeit85deg`; it is never represented by integer 8 or converted to minutes. Supported fixed minute values include 42, 50, 72 and validated custom minutes after sunset. The 72-minute option is explicitly fixed minutes, without implying all Rabbeinu Tam interpretations are equivalent.

Operational `close_before_candles_minutes` and `open_after_havdalah_minutes` affect group permissions only. Screens display candles, lock, havdalah and open independently. Calendar events require structured `yomtov=true`; a generic holiday is not prohibited work. Adjacent festival/Shabbat civil days form one interval, so intermediate candles never trigger opening.

The calendar is fetched separately with explicit `i=on/off`, avoiding a location-derived override of Israel/diaspora custom. Solar requests use exact coordinates and timezone with an explicit batch range. Missing required solar values stop automatic permission changes and reminders. No polar fallback is invented.

Civil dates select Daf Yomi. Omer evening uses the next civil date's structured Omer event; after midnight the current date continues that night. Counting progresses through non-send days. Night messages wait until chosen nightfall and quiet/lock end; daytime completion is separate, disabled by default and omits the blessing.

Sources: [Hebcal calendar](https://www.hebcal.com/home/195/jewish-calendar-rest-api), [zmanim](https://www.hebcal.com/home/1663/zmanim-halachic-times-api), [candle/havdalah](https://www.hebcal.com/home/4463/candle-lighting-havdalah-fast-times).

Current `is_shabbat` and `is_yom_tov` flags are calculated from active individual day segments. A merged festival/Shabbat sequence keeps one final opening time; its union of event metadata does not imply that every day in the sequence is both Shabbat and Yom Tov. `quiet_now` includes the configured early operational closure, even before the religious interval begins.

Omer phase is explicit: day, twilight or night. At sunset the next civil date's structured Omer event becomes the display count, but nighttime delivery waits for the chosen nightfall. After midnight the current civil date still identifies that counting night until verified dawn. Fixed times before noon are anchored on the following civil morning of the night being planned; a time beyond dawn does not create a night reminder. Optional daytime completion is a separate no-blessing behavior and is suppressed during the group's religious/operational quiet period. Night retry expiry never passes dawn.

Tefillin starts no earlier than the selected provider misheyakir and ends strictly before its effective cutoff. Observed Tish'a B'Av dates are taken from the provider's event date, including postponed fasts; a separate mincha policy requires verified mincha time. PHP weekday values stored by the UI (Sunday=0) are converted once to the planner's ISO weekday convention.

Provider responses validate ordered civil-date coverage, event dates, complete solar series and explicit timezone offsets. Solar nulls are retained for unavailable calculations; missing required values stop operations. Persistent raw-cache fallback on a Hebcal refresh error exposes stale status and its original fetch time, and still passes the same coverage checks. The timestamp of a new response is never treated as evidence of a current calendar range.

The 49 Hebrew/English count texts in `resources/templates/omer-counts.json` come from the attributed Hebcal dataset (CC-BY-4.0). The supported `ashkenaz`/`sephard` forms use ba-omer/la-omer suffix variants. Every locale preserves the authentic Hebrew count, including weeks and remaining days. French, Spanish, Russian and Brazilian Portuguese add a bundled static explanatory summary from `omer-counts-localized.json`; English retains Hebcal's summary. These summaries explain the count rather than replacing Hebrew ritual wording. No runtime language model or translation service composes prayers.

Full night form additionally includes the traditional blessing with localized eligibility wording; optional Ashkenaz preparation or the selected Sephard Leshem Yichud preparation; Harachaman; Psalm 67; Ana Bekoach; and the traditional concluding prayer with that day's sefira. Ashkenaz uses the short conclusion, while Sephard uses its extended conclusion. `sephard` here identifies the documented Nusach Sefard sequence; it is not a claim to support all Edot HaMizrach/Yemenite/custom variants. Day completion omits the blessing, preparation and additions. The application frames the night reminder with date, location, day number and relevant time separately.

`resources/templates/omer-liturgy.json` retains attribution, license, retrieval date and four immutable source revisions: [Ashkenaz 3017054](https://he.wikisource.org/w/index.php?title=סידור/נוסח_אשכנז/ספירת_העומר&oldid=3017054), [Sephard sequence 2929975](https://he.wikisource.org/w/index.php?title=סדר_ספירת_העומר&oldid=2929975), [Psalm 67 1014815](https://he.wikisource.org/w/index.php?title=תהלים_סז&oldid=1014815), and [Ana Bekoach 3085666](https://he.wikisource.org/w/index.php?title=אנא_בכח&oldid=3085666), checked 2026-10-13. It is a separately attributed CC-BY-SA-4.0 transcription of traditional liturgy: vowel points/cantillation removed, punctuation/line breaks normalized, divine name displayed as ה׳, and Ana Bekoach uses the source's documented רחמם alternative. Those pages' incomplete numbered count list was never used. No modern Sefaria English translation was copied. Automated tests cover all 49 days, six locales, exact variant distinctions/order, week transitions and Telegram text length; this does not represent personal rabbinic approval of an individual's blessing eligibility.

The current tefillin reminder start method is explicitly Hebcal `misheyakir`, 11.5 degrees below the morning horizon. The provider also returns `misheyakirMachmir` (10.2 degrees), but the current reminder form does not offer a selector for that second method. A missing/null selected misheyakir blocks scheduling; the code does not substitute dawn/sunrise or a guessed value. See the [provider method definitions](https://www.hebcal.com/home/1663/zmanim-halachic-times-api).

Internal language codes are `he`, `en`, `ru`, `fr`, `es`, `pt-br`. Calendar-provider requests map English to Hebcal `s` and Brazilian Portuguese to `pt`; the other four map directly. The [official language documentation](https://www.hebcal.com/home/4534/jewish-calendar-event-language-support) lists the Hebrew/English/Russian/French/Spanish options; the [official calendar form](https://www.hebcal.com/ical/) and a public `lg=pt` API request on 2026-10-13 confirmed Portuguese titles. `title_orig` retains the original event name used for fast/day classification, with original English `title` fallback when the provider omits a redundant original field. A display language change cannot change event restrictions.

## Complete solar response contract (dev.3)

Hebcal's times object combines daily solar series, empty elevation-only series and sparse monthly lunar events. The parser explicitly recognizes supported daily fields; seaLevelSunrise/seaLevelSunset, molad/Kiddush Levanah and unknown future extensions are not used as daily operational schedules. They do not make a valid daily response incomplete.

Sunset must exist and cover the requested dates. Every present supported daily series still needs complete coverage and strict timestamp/date/IANA validation; explicit null remains unavailable. The engine refuses missing selected sunrise/dawn/nightfall/sunset as required by each operation. The preceding-night chatzotNight exception remains bounded and separate. No missing operational time is synthesized.

Full unprojected fixtures for the exact default Jerusalem coordinates retain all 42 original fields and their raw metadata. They cover the real response shape that dev.2's seven-field projection missed. See the fixture provenance beside the files in tests/Fixtures.

For live read-only verification, run php bin/check-calendar.php --date=2026-10-15. It uses the actual public HTTP/calendar/solar pipeline, reports separate stages and safe reason codes, and does not open the live application database, load .env, authenticate Telegram or change permissions. October Omer is correctly reported inactive; in-season tests verify the actual provider's 49 counts and sunset/midnight phases.
